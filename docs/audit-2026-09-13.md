# 交付前审计 · 2026-09-13

把功能盘点的 76 项逐条对着代码和实测核一遍。**每一行的结论都有证据**：要么是跑过的
用例，要么是代码里的位置，要么是"确实 grep 不到"。

分三档：

- **必须做** —— 没有它，Orrery 替不掉你们现在在 GitHub Actions 上跑的东西
- **该做** —— 不阻塞替换，但缺了会在某一天咬人
- **卡在决策上** —— 代码量不是问题，缺的是一个你们要先定的东西

## 四、已验证可用（不再是计划）

触发：push / PR / tag、路径分支过滤、活动类型、`schedule`、`workflow_dispatch` 带类型参数、
API 触发、webhook 幂等。
定义：GH Actions 兼容 YAML、`needs:` DAG、矩阵、job 级 `if:`、`uses:` action、
**`services:` 边车容器**（实测 redis sidecar 返回 PONG）。
执行：容器与宿主两种 job、平台默认超时、并发组默认开启、带确认的协作式停止、
被打断记 `cancelled`。
数据面：实时日志流（扛住 12 万行）、产物与缓存（钉 v3）、跨 job outputs、
密钥注入与日志打码、日志容量上限、保留期。
回写与入口：commit status、变化才发的通知、CLI、Web UI（筛选分页 / 手动触发 /
run 级取消 / 日志折叠查找 / runner 与定时页）、重跑（attempt 归档）。
运维：认证、仓库白名单、残留清扫、systemd unit。
